012階建て見せ方（外向き／内向き）

既存7社・13万店舗ベースを混乱させずに「シエラ最上位」を成立させる構造

EXTERNAL · 外向き（営業・LP・既存顧客）

シエラ＝既存資産の「拡張レイヤー」

既存ローカル在庫／GBP管理／LFPは継続。シエラは「会話で実行する追加価値」として訴求。既存契約顧客（7社+α）を貶めず、自然な拡張として提案できる。
＋ シエラエージェント（会話実行レイヤー／追加価値）
ローカル在庫 / GBP管理 / 店舗集客 / LFP（既存・継続）
INTERNAL · 内向き（経営層・PdM・社内）

シエラ＝戦略OS

シエラエージェントを戦略OSとして最上位。ローカル在庫・チャット・GBP管理・店舗集客は配信先のソリューションとして整理。リソース配分の基準軸。
シエラエージェント（戦略OS／Planner-Executor-Validator）
↳ ローカル在庫 ＋ チャット（在庫×OMS実行）
↳ GBP管理 / 店舗集客 / LFP（配信先ソリューション）
運用ルール：外向き資料（LP／PoC1pager／既存顧客向け）では「拡張レイヤー」表現を使う。 内向き資料（経営層／PdMレビュー）では「戦略OS」表現を使う。2つの表現を混在させない。

03ICP定義（既存7社のパターン抽出）

「既存顧客の共通条件」から逆算したICP — シエラエージェントが効く企業像

業態 マルチストア小売（アパレル／カメラ・写真／リユース／ホームセンター／メガネ／スポーツ／家電量販）= 既存7業界カバー済
店舗数 30店舗〜500店舗（最小キタムラ30、最大アーバンリサーチ250+、ハードオフ300+）
必須① GMC運用 Google Merchant Center 運用済（offerId 把握） / カンリーアカウント（mca@can-ly.com）に読取権限付与可能
必須② GBP整備 Google Business Profile オーナー確認済 / 店舗コード（storeCode）保有 / GMCと整合性あり
必須③ 在庫データ連携 自社基幹システムから API（推奨）or SFTP で日次連携可能 / 必須5カラム（storeCode/offerId/price/availability/quantity）を出せる
CV単価帯 中〜高単価（カメラ 数万円〜数十万 / 家電 数万〜 / マットレス 数万〜 / DIY 数千〜 / アパレル 1.5万平均）
定性条件 ・「店舗を増やさず売上を伸ばす」DX意欲（カインズ「ホームセンターからIT小売企業へ」、上新電機「まごころサービス」）
・既存AI投資（音声AI / 店舗ナレッジAI）があり補完設計を受け入れる柔軟性
・成果報酬型課金（解決した分だけ）の説明が稟議に通る組織体力
・「Agentic Commerce時代の到来」に対応する意思（既存提案資料 slide 34-37 既に組み込み済）
除外 EC無し／在庫API連携不可／単店D2C（複数店舗まとめ買いシナリオ無し）／プラットフォーム依存型（楽天・Amazonのみ）

⚡ Why Now — Walmart Sparky 教訓 ＋ アーバンリサーチ既存組み込みの符合

米国：Walmart Instant Checkout（2025/9 OpenAI×Walmart）は「単品ごとチェックアウト」モデルでCVRが既存サイト1/3に低下。WalmartはSparky（アプリ/Web/ChatGPT/Geminiのバスケット同期）で再構築中。
日本：アーバンリサーチ向け提案資料（2026-05-27）slide 34-37 で「Agentic Commerce時代の到来」「将来的にgemini内でEC購買完結」が既に組み込まれている。
→ シエラエージェントは "新規方向の提案" ではなく "既に発信した方向の具体的な実装層"。藤林さん側のメッセージとも完全に整合。

マルチストア + 自社EC + 在庫API連携可能 + Tier 1類似業態

期待LTV：年$100K–$350K / アプローチ：Tier 1の事例コンテンツでInbound
TIER 3 · ボリュームターゲット

少数店 + 自社EC中心 + 在庫管理3PL + 単店D2C

店舗数20以下／EC比率が高い／在庫管理は3PL／単店D2Cブランド／成果報酬で量を獲得

07既存資産との接続関係

シエラエージェントは既存4資産にどう乗るか

🔗 カンリー既存資産との接続

  • ローカル在庫（GTM-B）：Sierraの実行レイヤー基盤。store×offer×price×availability×quantityの5カラムをチャット内で即時提示
  • GBP管理（一括返信／クチコミ）：SierraがGEO（生成AI最適化）に基づくブランドボイス返信を24h以内で自動化
  • 店舗集客（GTM-A）：来店前のチャット相談→店頭「Magic Links」引き継ぎ。CVR +25〜40%（仮説）
  • LFP（公式ローカルフィード）：Google認定パートナー認定＝Sparky型 Universal Commerce Protocol への接続性確保済

⚠️ Sparky型「リアルタイム同期」と公式日次の差分

  • 公式運用は日次連携がベース → カゴ落ち防止にはタイムラグ大
  • API秒間100回までは技術的可能 → 「シエラ専用リアルタイム層」の別開発が必要
  • 既存ベンダー連携（CSVバッチ）の上にSierra専用の差分同期APIを載せる設計
  • これは藤林さん×PdM議論の必須論点（Open Question #4 参照）

09Open Questions（v0.2で3問Resolved）

藤林さんレビュー必須項目 — 6/3資料で3問解決済

✅ Q1（在庫API粒度）— Resolved
公式は日次連携が推奨／API利用時のみ秒間100リクエストまで／1ファイル5GB以内／国内IPのみ。
→ シエラ Sparky型「バスケット同期＋まとめ取り置き」は既存日次連携の上にシエラ専用リアルタイム層を別開発する設計が必要。
✅ Q2（PoC1社目アプローチルート）— Resolved
カインズ・キタムラとも既存顧客（カンリーローカル在庫を運用中）と判明。新規PoCではなく既存CS経由のシエラ拡張β提案が最短。月次レポート運用が稼働しているキタムラから先行が現実的。
✅ Q3（必須データ仕様）— Resolved
在庫フィード必須5カラム（storeCode/offerId/price/availability/quantity）。これがシエラチャット応答の最小データ単位。シエラ側Output生成のスキーマもこれに準拠。
